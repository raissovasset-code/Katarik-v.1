# Катарик

Онлайн-карточная игра для компьютеров, телефонов и планшетов. Игроки создают комнату, приглашают друзей по ссылке и играют в реальном времени.

**Рабочая версия:** [katarik-5g25.onrender.com](https://katarik-5g25.onrender.com)

## Что уже работает

- комнаты до 11 игроков;
- режимы «Обычный», «На вылет» и «Погоны»;
- отдельные интерфейсы для компьютера и мобильных устройств;
- автоматическое определение типа устройства;
- игра через WebSocket в реальном времени;
- восстановление соединения после кратковременного обрыва;
- Android-приложение на Capacitor;
- автоматическое развертывание веб-версии на Render.

## Требования

Для веб-разработки:

- Node.js 20 или новее;
- npm.

Дополнительно для Android:

- JDK 17 или новее;
- Android Studio;
- Android SDK и Platform Tools (`adb`).

## Локальный запуск

Откройте два терминала в корне проекта.

Первый терминал — сервер:

```powershell
npm install --prefix server
npm run dev --prefix server
```

Второй терминал — клиент:

```powershell
npm install --prefix client
npm run dev --prefix client
```

Откройте [http://localhost:5173](http://localhost:5173). Сервер работает на `http://localhost:3001`.

Vite показывает также сетевой адрес вида `http://192.168.x.x:5173`. Его можно использовать для локальной проверки на телефоне, если компьютер и телефон подключены к одной сети.

## Выбор интерфейса

Игра автоматически определяет устройство:

- на компьютере открывается компьютерная версия;
- на телефоне открывается мобильная версия.

Для принудительной проверки доступны параметры:

- `?view=desktop` — компьютерный интерфейс;
- `?view=mobile` — мобильный интерфейс.

Пример: `http://localhost:5173/?view=mobile`.

## Архитектура

```text
KatarikProject/
├── client/                  React + Vite, интерфейс игры
│   ├── public/              карты, стол и другие изображения
│   └── src/                 компоненты, состояние и стили
├── server/                  Express + WebSocket
│   └── src/
│       ├── index.js         HTTP/WS-сервер и обработка команд
│       ├── game.js          правила и состояние игры
│       └── game.test.js     серверные тесты правил
├── android/                 нативный Android-проект Capacitor
├── scripts/                 сборка мобильной версии и проверки среды
├── capacitor.config.json    конфигурация Android-приложения
└── render.yaml              конфигурация Render
```

Клиент отправляет игровые команды серверу по WebSocket. Сервер является источником истины: хранит комнаты, проверяет ходы и рассылает актуальное состояние игрокам. В production Express также раздает собранный клиент из `client/dist`.

Комнаты без игроков удаляются сразу. Если все игроки отключились, комната удаляется после одного часа без активности. Период можно настроить переменными `ROOM_TTL_MS` и `ROOM_CLEANUP_INTERVAL_MS`; значения задаются в миллисекундах.

При наличии `REDIS_URL` сервер сохраняет каждое изменение комнаты в Redis-совместимое хранилище и загружает комнаты до запуска WebSocket-сервера. Поэтому игроки могут переподключиться после перезапуска или развертывания веб-сервера. Без `REDIS_URL` сервер продолжает работать в памяти и выводит предупреждение при запуске.

## Production-сборка

Из корня проекта:

```powershell
npm run build
npm start
```

Команда `build` устанавливает зависимости сервера и клиента, затем собирает React-приложение. После запуска готовая игра доступна на `http://localhost:3001`.

## Render

Render использует файл `render.yaml`:

- сборка: `npm run build`;
- запуск: `npm start`;
- ветка развертывания: `main`;
- автоматическое обновление после отправки изменений в GitHub;
- отдельное Key Value хранилище `katarik-rooms`, доступное серверу через `REDIS_URL`.
- разрешенные HTTP/WebSocket origins задаются через `ALLOWED_ORIGINS`; production разрешает только опубликованный сайт и локальный origin Android Capacitor.

Состояние подключения хранилища можно проверить по адресу [`/api/health`](https://katarik-5g25.onrender.com/api/health): в production поле `roomStorage` должно иметь значение `redis`.

Бесплатный сервер Render засыпает при бездействии. Первое открытие после паузы может занять около 50 секунд; это не означает, что приложение сломано. Бесплатное Key Value хранилище переживает перезапуск веб-сервера, но не имеет дисковой персистентности на случай сбоя самого хранилища.

## Android

Сначала установите зависимости в корне проекта:

```powershell
npm install
```

Проверьте Android-среду и синхронизируйте проект:

```powershell
npm run android:check
npm run cap:sync
npm run android:open
```

`cap:sync` собирает мобильный клиент с production WebSocket-адресом и копирует его в Android-проект.

### Debug APK

```powershell
cd android
.\gradlew.bat assembleDebug
```

Файл появится здесь:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

### Подписанные APK и AAB

1. Создайте release-ключ и сохраните его в безопасном месте.
2. Скопируйте `android/signing.properties.example` в `android/signing.properties`.
3. Заполните путь к ключу, alias и пароли.
4. Выполните сборку:

```powershell
cd android
.\gradlew.bat assembleRelease
.\gradlew.bat bundleRelease
```

Результаты:

```text
android/app/build/outputs/apk/release/app-release.apk
android/app/build/outputs/bundle/release/app-release.aab
```

APK нужен для установки на телефон, AAB — для публикации в Google Play. Настоящий ключ и файл `android/signing.properties` нельзя отправлять в GitHub.

## Проверки

Серверные тесты правил:

```powershell
npm test
```

Проверка сборки клиента:

```powershell
npm run build --prefix client
```

Проверка Android-среды:

```powershell
npm run android:check
```

Перед публикацией рекомендуется проверить создание комнаты, подключение нескольких игроков, все три режима, переподключение и выход игрока отдельно на компьютере и телефоне.

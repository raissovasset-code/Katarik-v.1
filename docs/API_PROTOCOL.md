# REST и WebSocket-протокол «Катарика»

Документ описывает фактический протокол текущего клиента и сервера. Игровые правила вынесены в [`GAME_RULES.md`](../GAME_RULES.md).

## Адреса

Production:

- HTTPS: `https://katarik-5g25.onrender.com`;
- WebSocket: `wss://katarik-5g25.onrender.com`.

Локальная разработка:

- HTTP: `http://localhost:3001`;
- WebSocket: `ws://localhost:3001`.

WebSocket подключается к корню сервера без дополнительного path. Каждое сообщение в обе стороны является одним JSON-объектом.

В текущем протоколе ещё нет поля версии. Клиент и сервер должны обновляться согласованно при несовместимом изменении формата.

## REST API

### `GET /api/health`

Проверяет, что процесс сервера отвечает. Успешный ответ — HTTP `200`:

```json
{
  "name": "Katarik server",
  "status": "ok",
  "roomStorage": "redis",
  "rooms": 3
}
```

Поля:

- `roomStorage`: `redis` или `memory`;
- `rooms`: количество комнат, загруженных в текущем процессе.

### `GET /api/ready`

Проверяет готовность хранилища и WebSocket-сервиса.

Успешный ответ — HTTP `200`:

```json
{
  "status": "ready",
  "checks": {
    "roomStorage": true,
    "websocket": true
  }
}
```

При неготовности хотя бы одного компонента сервер возвращает HTTP `503`:

```json
{
  "status": "not_ready",
  "checks": {
    "roomStorage": false,
    "websocket": true
  }
}
```

## Общие правила WebSocket

- Кодировка сообщений — UTF-8 JSON.
- Поле `type` обязательно.
- Неизвестный `type`, некорректный JSON или неверные поля дают сообщение `error`.
- После входа сервер связывает WebSocket с конкретным игроком и комнатой. Игровые команды используют эту привязку, а не переданный повторно `playerId`.
- Секрет `sessionToken` нужен для создания места и последующего восстановления того же места. Его нельзя выводить в логи, URL или интерфейс.
- После успешного изменения комнаты сервер рассылает каждому подключённому игроку персональное сообщение `state`.
- Отдельного request id и отдельного подтверждения для большинства команд нет. Подтверждением служит новое `state` либо `error`.

## Идентификация игрока

Поля идентификации:

```json
{
  "playerId": "8e9fb78c-...",
  "sessionToken": "b65a4fc6-...",
  "name": "Асет"
}
```

Ограничения:

- `playerId`: непустая строка до 128 символов;
- `sessionToken`: непустая строка до 256 символов;
- `name`: строка до 32 символов, может отсутствовать;
- отображаемые имена внутри комнаты автоматически делаются уникальными.

При повторном `joinRoom` с теми же `playerId` и `sessionToken` игрок получает прежнее место. Совпадающий `playerId` с другим токеном отклоняется.

## Сообщения клиента

### `ping`

Проверка соединения. Не ограничивается rate limit.

```json
{ "type": "ping" }
```

Ответ: `pong`.

### `createRoom`

Создаёт комнату и назначает отправителя хозяином.

```json
{
  "type": "createRoom",
  "mode": "classic",
  "playerId": "player-id",
  "sessionToken": "private-token",
  "name": "Асет"
}
```

`mode` обязателен:

- `classic` — обычный режим;
- `elimination` — на вылет;
- `pogoni` — погоны.

Ответы: сначала `roomCreated`, затем `state`.

### `joinRoom`

Входит в существующее лобби или восстанавливает прежнее место игрока.

```json
{
  "type": "joinRoom",
  "roomId": "ABC123",
  "playerId": "player-id",
  "sessionToken": "private-token",
  "name": "Асет"
}
```

`roomId` — ровно шесть латинских букв или цифр. Сервер приводит код к верхнему регистру.

Новый игрок может войти только в лобби. Уже существующий игрок с правильным токеном может восстановить подключение после обрыва или перезапуска сервера.

Ответ: `state`.

### `addBot`

Добавляет серверного бота.

```json
{ "type": "addBot" }
```

Доступно только хозяину в лобби. Общий предел — 11 игроков вместе с ботами.

Ответ: обновлённый `state`.

### `leaveRoom`

Покидает комнату.

```json
{ "type": "leaveRoom" }
```

Ответ отправителю: `leftRoom`. Остальным игрокам отправляется новое `state`, если комната продолжает существовать.

Выход во время партии обрабатывается по правилам выбранного режима и может завершить игру или отложить удаление места до конца кона.

### `kickPlayer`

Удаляет другого игрока из лобби.

```json
{
  "type": "kickPlayer",
  "targetPlayerId": "other-player-id"
}
```

Доступно только хозяину и только до начала игры. Хозяин не может удалить сам себя.

Удалённый игрок получает `kicked`, остальные — новое `state`.

### `startGame`

Начинает партию из лобби.

```json
{ "type": "startGame" }
```

Доступно только хозяину. Минимум:

- 2 игрока для `classic` и `pogoni`;
- 3 игрока для `elimination`.

Ответ: `state`.

### `restartGame`

Начинает игру заново в той же комнате.

```json
{ "type": "restartGame" }
```

Доступно только хозяину. Игроки, окончательно покинувшие комнату, удаляются перед новой раздачей.

Ответ: `state`.

### `nextRound`

Начинает следующий кон.

```json
{ "type": "nextRound" }
```

Доступно хозяину в режимах `elimination` и `pogoni`.

Ответ: `state`.

### `play`

Разыгрывает выбранные карты.

```json
{
  "type": "play",
  "cardIds": ["7H", "7D", "DVK"],
  "declaredRanks": {
    "DVK": "7"
  }
}
```

Ограничения формата:

- `cardIds` — непустой массив не более чем из 55 элементов;
- каждый id — непустая строка до 32 символов;
- повторяющиеся id запрещены;
- `declaredRanks` — необязательный объект;
- допустимые объявленные ранги: `4`, `5`, `6`, `7`, `8`, `9`, `10`, `J`, `Q`, `K`, `A`, `2`, `3`.

`declaredRanks` применяется к дикой карте `DVK`, когда серверу нужно однозначно определить группу. Сервер дополнительно проверяет наличие карт в руке, очередь хода, комбинацию и возможность побить стол.

Ответ: `state` или `error`.

### `pass`

Пасует на текущем столе.

```json
{ "type": "pass" }
```

Доступно только игроку, чей сейчас ход, и только если стол не пуст.

Ответ: `state` или `error`.

## Сообщения сервера

### `pong`

```json
{
  "type": "pong",
  "timestamp": 1784995200000
}
```

`timestamp` — серверное время Unix в миллисекундах.

Текущий клиент отправляет `ping` каждые 10 секунд. Если сообщений от сервера нет более 30 секунд, клиент закрывает соединение и запускает переподключение с задержкой до 8 секунд.

### `roomCreated`

```json
{
  "type": "roomCreated",
  "roomId": "ABC123"
}
```

После него сервер отправляет `state`.

### `state`

```json
{
  "type": "state",
  "game": {
    "roomId": "ABC123",
    "mode": "classic",
    "status": "playing",
    "hostPlayerId": "player-1",
    "currentPlayerId": "player-2",
    "players": [],
    "hand": [],
    "table": null
  }
}
```

Состояние персонализировано: поле `hand` содержит только карты получателя. Карты соперников и сожжённые карты не передаются.

### `leftRoom`

```json
{ "type": "leftRoom" }
```

Подтверждает добровольный выход.

### `kicked`

```json
{
  "type": "kicked",
  "message": "Хозяин комнаты удалил вас из комнаты."
}
```

### `error`

```json
{
  "type": "error",
  "message": "Сейчас ход другого игрока"
}
```

`message` предназначен для показа пользователю. Клиент не должен определять бизнес-логику по тексту ошибки, кроме существующего восстановления соединения. В протоколе пока нет машинного `errorCode`.

## Публичное состояние игры

Объект `game` содержит:

| Поле                 | Тип         | Назначение                                          |
| -------------------- | ----------- | --------------------------------------------------- |
| `roomId`             | string      | Код комнаты                                         |
| `mode`               | string      | `classic`, `elimination` или `pogoni`               |
| `status`             | string      | `lobby`, `playing`, `round_finished` или `finished` |
| `hostPlayerId`       | string/null | Текущий хозяин комнаты                              |
| `players`            | Player[]    | Публичные сведения об игроках                       |
| `hand`               | Card[]      | Только рука получателя                              |
| `table`              | Table/null  | Текущая комбинация на столе                         |
| `currentPlayerId`    | string/null | Чей ход                                             |
| `lastPlayedPlayerId` | string/null | Кто последним сыграл                                |
| `passedPlayerIds`    | string[]    | Кто спасовал в текущем розыгрыше                    |
| `pogonReadyPlayerId` | string/null | Кто забрал стол и может поставить погон             |
| `roundStarterId`     | string/null | Кто начал текущий кон                               |
| `roundWinnerId`      | string/null | Победитель завершённого кона                        |
| `eliminatedIds`      | string[]    | Выбывшие игроки                                     |
| `places`             | string[]    | Порядок закончивших карты                           |
| `loserId`            | string/null | Проигравший завершённой игры                        |
| `dealOffset`         | number      | Серверное смещение раздачи между конами             |
| `lastActivityAt`     | number      | Последняя активность комнаты, Unix ms               |

`burned` намеренно исключается из JSON-ответа.

### Player

```json
{
  "id": "player-1",
  "name": "Асет",
  "active": true,
  "leaving": false,
  "isBot": false,
  "handCount": 12,
  "pogonRank": "4"
}
```

Приватный токен и карты руки игрока в `players` отсутствуют.

### Card

Обычная карта:

```json
{
  "id": "10S",
  "rank": "10",
  "suit": "S",
  "type": "normal"
}
```

Масти: `S`, `H`, `D`, `C`.

Особые карты:

```json
{ "id": "BLACK_JOKER", "rank": "BLACK_JOKER", "suit": null, "type": "joker" }
{ "id": "RED_JOKER", "rank": "RED_JOKER", "suit": null, "type": "joker" }
{ "id": "DVK", "rank": "DVK", "suit": null, "type": "wild" }
```

### Table и Combo

```json
{
  "playerId": "player-2",
  "cards": [
    { "id": "8S", "rank": "8", "suit": "S", "type": "normal" },
    { "id": "8H", "rank": "8", "suit": "H", "type": "normal" }
  ],
  "combo": {
    "type": "pair",
    "high": 5,
    "length": 2
  }
}
```

Типы `combo`:

- `single`;
- `pair`;
- `triple`;
- `quad`;
- `straight`;
- `doubleStraight`.

`high` — внутреннее числовое старшинство старшей карты; `length` — количество карт, а для `doubleStraight` количество пар.

## Ограничение запросов

На один процесс сервера действуют скользящие лимиты:

| Группа            | Лимит                                |
| ----------------- | ------------------------------------ |
| `createRoom`      | 5 в минуту на IP                     |
| `joinRoom`        | 30 в минуту на IP                    |
| остальные команды | 120 в минуту на WebSocket-соединение |
| `ping`            | без лимита                           |

При превышении лимита сервер отправляет `error` с рекомендуемым временем ожидания.

## Origin и безопасность

- Браузерные HTTP и WebSocket origin проверяются по `ALLOWED_ORIGINS`.
- Клиенты без заголовка `Origin` разрешены для нативных и служебных проверок.
- Сервер является единственным источником истины для хода, рук и результата.
- Нельзя считать поля клиента подтверждением права хозяина или владения картой.
- `sessionToken` должен храниться только на устройстве игрока и передаваться внутри защищённого `wss`.
